* Async

Usecase: Loading something from the API etc.

* Loading data with Resources

- Type: [[https://docs.rs/leptos/latest/leptos/struct.Resource.html][Resource]]
  - Signal that reflects that the current state of an asynchronous task.
  - Allows to integrate with async Futures.
  - Created using [[https://docs.rs/leptos/latest/leptos/fn.create_resource.html][create_resource]] function.

** create_resource function

Arguments:
- Source signal which will generate a new ~Future~ whenever it changes.
- A fetcher function which takes the data from the signal and returns
  a future.

#+begin_src rust
// our source signal: some synchronous, local state
let (count, set_count) = create_signal(0);

// our resource
let async_data = create_resource(
    count,
    // every time `count` changes, this will run
    |value| async move {
        logging::log!("loading data from API");
        load_data(value).await
    },
);
#+end_src

Another example:

#+begin_src rust
[component]
fn SomeComponent() -> impl IntoView {
    let (count, set_count) = create_signal(0);

    let async_data = create_resource(count, |value| async move {
        logging::log!("loading data from API");
        "Some data from API".to_owned()
    });

    let click_handler = move |_| set_count.update(|count| *count += 1);

    view! {
        <button on:click=click_handler>"Click me: " {move || count()} </button>
        {
            move || match async_data.get() {
                None => view! { <p>"Loading..."</p>}.into_view(),
                Some(data) => view! { <p> {data} </p>}.into_view()
        }
        }
    }
}
#+end_src


* <Suspense />

- In the last example, we handle the loading case ourselves. What if
  there are 100 such resources ? Pattern matching on all of them
  becomes annoying.
- Solution: Suspense component
- It has a ~fallback~ prop and children. When they are all loaded, it
  shows the children.

#+begin_src rust
#[component]
fn SomeComponent() -> impl IntoView {
    let (count, set_count) = create_signal(0);
    let (count2, set_count2) = create_signal(0);

    let async_data_one = create_resource(count, |value| async move {
        "Some data from API (1)".to_owned()
    });

    let async_data_two = create_resource(count2, |value| async move {
        logging::log!("loading data from API (2)");
        "Some data from API (2)".to_owned()
    });

    let click_handler = move |_| set_count.update(|count| *count += 1);

    view! {
        <button on:click=click_handler>"Click me: " {move || count()} </button>
        <Suspense fallback=move || view! {<p>"Loading..."</p>} >
        <h2> "My data:" </h2>
        <div> "Count 1:" {async_data_one.get().map(|a| view! {<p>{a}</p>})} </div>
        <div> "Count 2:" {async_data_two.get().map(|a| view! {<p>{a}</p>})} </div>
        </Suspense>
    }
}
#+end_src

* <Await />

- Motivation: Waiting for some future to be resolve before rendering.
  - It only polls the ~Future~ once and does not respond to any
    reactive changes.
  - Does not render anything until the ~Future~ resolves.
  - After the ~Future~ resolves, it binds the data to the variable
    name you chose and then renders its children with the variable in
    scope.

#+begin_src rust
async fn fetch_monkeys(monkey: i32) -> i32 {
    // maybe this didn't need to be async
    monkey * 2
}

#[component]
fn SomeComponent() -> impl IntoView {
    view! {
    <Await
        // `future` provides the `Future` to be resolved
        future=|| fetch_monkeys(3)
        // the data is bound to whatever variable name you provide
        let:data
    >
        // you receive the data by reference and can use it in your view here
        <p>{*data} " little monkeys, jumping on the bed."</p>
    </Await>
    }
}
#+end_src

* <Transition />

- In the *<Suspense />* example, if you keep reloading the data - it
  keeps flickering to ~"Loading..."~.
- If you don't want that, you can use *<Transition />* component.
- It will show the fallback only for the first time. For subsequent
  load, it shows the old data untill the new data are ready.

#+begin_src rust
#[component]
fn SomeComponent() -> impl IntoView {
    let (count, set_count) = create_signal(0);
    let (count2, set_count2) = create_signal(0);

    let async_data_one = create_resource(count, |value| async move {
        "Some data from API (1)".to_owned()
    });

    let async_data_two = create_resource(count2, |value| async move {
        logging::log!("loading data from API (2)");
        "Some data from API (2)".to_owned()
    });

    let click_handler = move |_| set_count.update(|count| *count += 1);

    view! {
        <button on:click=click_handler>"Click me: " {move || count()} </button>
        <Transition fallback=move || view! {<p>"Loading..."</p>} >
        <h2> "My data:" </h2>
        <div> "Count 1:" {async_data_one.get().map(|a| view! {<p>{a}</p>})} </div>
        <div> "Count 2:" {async_data_two.get().map(|a| view! {<p>{a}</p>})} </div>
        </Transition>
    }
}
#+end_src

* <Action />

- create_resource: If you’re trying to load data by running an async
  function, either once or when some other value changes, you probably
  want to use create_resource.
- create_action: If you’re trying to occasionally run an async
  function in response to something like a user clicking a button, you
  probably want to use create_action.


Example code:

#+begin_src rust
async fn some_async_function(input: &String) -> String {
    match &input[..] {
        "hi" => "hello".to_owned(),
        "bye" => "Bye bye".to_owned(),
        _ => "Hmm..".to_owned(),
    }
}

#[component]
fn SomeComponent() -> impl IntoView {
    let (count, set_count) = create_signal(0);
    let action = create_action(|input: &String| {
        let input = input.to_owned();
        async move { some_async_function(&input).await }
    });

    let click_handler = move |_| {
        set_count.update(|count| *count += 1);
        let count = count();
        if count > 10 {
            action.dispatch("bye".to_owned());
        } else if count > 3 {
            action.dispatch("hi".to_owned());
        }
    };

    let value = action.value();

    view! {
        <button on:click=click_handler>"Click me: " {move || count()} </button>
        <p>"Data: " {move || format!("{:#?}", value()) }</p>
    }
}
#+end_src
